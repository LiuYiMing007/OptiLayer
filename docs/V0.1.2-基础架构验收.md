# v0.1.2 基础架构验收

日期：2026-10-30。开发环境：Apple Silicon macOS。本次依据《项目技术路线调整-跨平台离线优先AI原生》评估并调整现有项目；未启动 AI Agent 或膜系优化。

## 结论

当前生产计算仍为 Python / NumPy / SciPy；Tauri + React 桌面界面保留。长期以 Rust 原生 / WASM 同源核心为优先方向，但必须经过完整物理模型、复数分支、性能及未来优化需求验证才替换。没有为了技术路线重写正确公式，也没有维护两套生产算法。详见《技术路线决策-跨平台离线优先》。

## 验证

- 自动化测试：28 项 Python + 4 项 TypeScript 通过。
- 独立光谱验收：25 项通过；Golden 301 点最大误差约 7.838×10⁻⁷ 个百分点。
- 前端生产构建及 Rust 原生编译通过；Plotly 包体积提示仍存在，不影响本次功能。
- 打包引擎：项目/材料保存 → 121 点光谱归档 → 整个工作区移动至另一中文路径 → 加载项目重新计算，结果逐值一致。
- 工作区错误处理：拒绝绝对/越界路径、未知未来版本、缺失挂载位置、过期光谱归档；JSON 副本写入失败仍保留已提交的数据库并返回提示。
- 原生首次升级：旧 schema v2 的 3 个项目复制到默认 Workspace schema v3，项目清单一致；原数据库与备份逐字节相同。
- 原生保存检查发现并修复 JSON 字段顺序造成的误判：保存后结果错误过期、光谱归档被跳过。规范化比较后以重新打包的原生应用复核。
- 原生界面新建「跨平台验收」工作区；编辑第一层厚度 72 nm、入射角 25° 后计算并保存；检查 SQLite、项目 JSON 及光谱归档，退出重启后再次打开项目并保存成功。验收后已切回包含用户原有项目的默认工作区。

## 尚未验证和未实现

Windows 客户端尚未在 Windows 编译和运行；Mac→Windows→Mac 的实机 SSD 往返待验收。目前的移动测试在本机不同路径间进行，不能替代跨系统和真实外置磁盘验收。Mac 应用没有 Developer ID 签名和公证。

浏览器独立产品、Rust/WASM 实现、同步、冲突合并、恢复副本自动重建数据库、配置面板、完整 imports 管理、吸收/色散、优化器、AI Agent 均未实现。目录和服务边界只为后续扩展提供基础。

SQLite 为权威存储；JSON 是恢复副本，不支持直接编辑 JSON 后自动覆盖数据库。移动 Workspace 前需关闭应用并复制整个目录。

下一步先完成 Windows 与真实 SSD 往返验收，再增加有来源和适用波段的真实材料数据、色散/吸收模型及独立物理验证，继续巩固第一条完整业务链路。
