# Workspace 数据规范 v1

## 0.1.4 便携项目层

程序与数据共同放在一个项目文件夹：根部 `tfc-project.json` 标记项目；`macOS/TFC.app` 和 `Windows/TFC.exe` 为各自客户端；`Workspace/` 为默认工作区。工作区内部格式仍为 v1，没有改变已保存的材料、膜系和光谱数据。

最近选择保存在项目 `.tfc/workspace-selection.json`，格式为 `{"schema_version":1,"workspace_relative":"Workspace"}`。设置只允许项目内相对路径；整体搬迁后沿新根目录解析，不采用机器的旧绝对偏好。新建/打开仅接受项目内部目录；外部完整工作区通过“迁入旧工作区（复制）”保留原件并复制到项目内，再记住新的相对位置。应用不在不可写或缺失时退回其它盘。

开发浏览器预览仍隔离在源码目录的 `.dev-workspace`，不代表桌面默认位置。

## 目录

```text
OpticalWorkspace/
├── workspace.json
├── projects/     # 按稳定项目 ID 导出的 JSON 恢复副本
├── materials/
│   ├── catalogue/  # TFCalc-0.2.0.original.json 原始目录快照
│   └── custom/     # 可读名称加稳定 ID 哈希的 *.material.json 恢复副本
├── spectra/      # 保存项目时保留的有效计算结果
├── database/
│   └── workspace.sqlite3
├── imports/      # 预留的原始导入资料目录
├── exports/      # 桌面文件导出的默认位置
└── config/       # 预留的非秘密工作区设置目录
```

SQLite 是项目与共享材料的主存储；JSON 是可阅读、可手动导入的恢复副本，不在读取时自动与数据库合并。光谱目录保存结果与其输入快照，数据库只记录稳定 ID 和 POSIX 相对路径；目前没有光谱历史管理界面。

imports 和 config 已建立目录，但没有自动归档导入文件或完整配置编辑功能。不把目录存在误认为相应业务已经完成。程序置于便携项目的 macOS、Windows 子目录，位于 Workspace 外，不参与工作区数据解释。

## Manifest

格式名称 `tfc-workspace`，`schema_version=1`。包含工作区 UUID、名称、创建时间、相对目录映射、单位（波长与物理厚度 nm、光谱 percent）。不保存所在电脑、盘符或绝对根目录。

宿主提供运行时根目录；Windows 可为盘符路径，Mac 可为挂载目录。从 0.1.4 起，宿主从程序所属项目目录解析项目内相对位置。原本机 workspace-selection.json 不再用于桌面默认选择。

## 数据规则

- 文本统一 UTF-8、JSON 数字与地区小数点格式无关。
- 内部文件名使用稳定 ID / 哈希，避免跨平台保留字符、大小写和中文文件名歧义；用户名称保留在内容中。
- 内部引用使用 `/` 的相对格式；通过 pathlib 解析到本机路径。拒绝盘符、UNC、上级目录和逃逸到工作区外的符号链接。
- 未支持的未来 Workspace 或数据库版本明确拒绝，不自动降级覆盖。
- 当前项目格式保持 schema_version=1，不重写已验证的材料/膜系数据模型。
- SQLite schema v3 沿用 projects/materials，新增 spectra；使用 DELETE journal 和 FULL synchronous。所有请求结束会关闭连接。
- 复制工作区之前退出应用，并复制整个目录。异常断开后的 journal 可能参与恢复，不应只复制主数据库后自行删除日志。
- 工作区支持在 Mac / Windows 间顺序使用；不提供网络共享并发写、多设备同步或冲突合并。驱动器不可用时提示重新选择，不在旧挂载位置偷偷创建空数据。
- 本地应用不需要访问网络；AI 配置和密钥不进入项目文件或可迁移工作区，未来密钥放在设备安全存储中。

## 保存与失败语义

先以数据库事务保存项目/材料，再生成可移植的 JSON 恢复副本。副本写入失败会返回警告，但不会假称数据库事务失败或丢弃已提交数据。JSON 通过同目录临时文件和原子替换写入。

只有计算输入与数据库中已保存项目的物理输入一致时，才保存光谱。光谱文件包含完整输入快照和单位，内部索引不含绝对路径。光谱历史界面和旧文件清理尚未实现。

## 旧版迁移

0.1.2/0.1.3 曾通过首次升级复制旧数据库。从 0.1.4 起，旧完整 Workspace 使用界面的“迁入旧工作区（复制）”，通过 SQLite backup API 复制到项目内新目录；保留原文件。只向已知空目标导入，不覆盖已有项目、光谱或修改过的材料库。迁移保留项目 ID、物理厚度、材料常数及原始数据；读取时沿用已验证的模型迁移逻辑。

项目内已有完整工作区使用「打开项目内工作区」；项目外数据先复制迁入，不能把 v3 数据库当作旧版单文件迁移，因为还需要 spectra 等文件。

## CLI 与开发预览

```sh
node scripts/run_python.mjs engine/main.py --workspace ./MyWorkspace --create-workspace
```

该命令从 stdin 接收 JSON。例如 `{"action":"workspace_info"}`。也可显式设置 TFC_WORKSPACE_ROOT。未指定工作区时纯计算仍能执行，数据操作明确报错，绝不回退到某个隐藏的用户目录。

开发预览默认创建项目下 .dev-workspace，与真实桌面数据隔离；通过 TFC_WORKSPACE_ROOT 可选择已有工作区。开发服务器只监听本机。正式浏览器 localhost 服务尚未实现。

## 验收

- 新建 → 添加材料 → 编辑膜系 → 计算 R/T → 保存 → 重新打开。
- 将包含中文路径的整个工作区移动到另一目录，保持 ID，重新加载并得到相同光谱。
- 旧版复制迁移后源文件字节不变；已有目标拒绝覆盖。
- 过期光谱拒绝归档；副本写入失败仍可从 SQLite 读取已保存项目。
- Windows 路径字符串、POSIX 绝对路径与父目录逃逸拒绝。
- 当前版本 Windows CI 必须实际运行后才可将其对应检查标为通过；本机结果不替代 Windows。

## 0.2.0 材料模型附加字段

内置 TFCalc 目录随程序只读分发，不自动覆盖现有工作区共享库。项目选用条目时存储完整 `samples` 或 `formula`、`range_nm`、来源及 SHA-256；目录摘要不能保存为计算材料。SQLite 表和 workspace manifest 版本不变，项目仍为 schema_version=1，以可选字段兼容原常数项目。0.1.x 不能计算新增的 tabulated / tfcalc-formula 模型；使用这些数据的项目需 0.2.0 及以上打开。

项目内仅存实际选用材料，仍最多 300 种，不复制全部 1,211 项。移动 Workspace 后不依赖原 TFCalc 文件路径，也不依赖原电脑的目录。

## 0.2.1 启动恢复与材料编辑

macOS AppTranslocation 隔离目录和未带项目标记的 Applications 目录不能推断固态盘上的真实数据位置。此时明确报错，用户通过工作区设置“选择便携项目位置…”选择实际 TFC 文件夹或已有 Workspace。原本已记住但缺失的 Workspace 不会偷偷新建。初次连接保留当前内存中的项目。Finder 的 .DS_Store 等普通元数据文件不再妨碍创建空工作区，其它内容仍拒绝覆盖。

显式恢复选择另在设备应用配置目录保存 project-location.json，作为隔离启动时的本机定位提示；这是宿主偏好，不进入 Workspace、不上传、不作为跨平台数据引用。正常从便携项目启动始终优先当前程序所属项目；换电脑或磁盘位置变更后可重新选择。项目内的工作区选择仍使用相对路径。

内置 1211 条目录即使尚未连接 Workspace 也可查询；连接后将完整原始目录导出至 materials/catalogue/TFCalc-0.2.0.original.json，已有文件不覆盖。材料数据没有改变，因此文件的数据版本仍为 0.2.0。编辑内置记录产生 USER/ 独立副本，保存至 SQLite 共享库和 materials/custom/可读名称-哈希.material.json，并更新当前项目引用，项目修改可撤销。原始条目保留，历史项目快照不会自动更新。

JSON 是恢复副本，不监控外部文件变化。建议在软件中编辑；外部修改后使用材料窗口“导入 JSON”，支持单个材料或材料数组，验证后再加入项目并保存到共享库。重命名可能留下旧名恢复副本，不自动删除用户文件；数据库仍是权威数据。原有根目录哈希文件保留。

## 0.2.2 定位隔离修正

取消 0.2.1 新增的本机 project-location.json 自动恢复和写入。旧文件可以保留，但新版完全忽略。仅从程序所属便携项目解析相对工作区，或使用本次会话中用户明确选择的项目。AppTranslocation/未关联 Applications 启动无法推断原目录时，明确提示选择；不采用别的安装、验收程序或过往路径。隔离启动可能需要每次明确选择，这是当前可见的限制，不能以恢复体验为由静默连错数据。

主窗口“数据位置”入口显示连接状态，并可查看真实完整路径，打开工作区、膜系、材料与基底、光谱及导出目录。膜系需要保存后才落盘。材料与基底共用 materials；tfc-project.json 只是便携目录标记。

验收程序必须通过 Tauri 构建配置的 identifier 隔离（例如 com.tfc.workbench.qa022），不能仅修改 .app 的 Info.plist；后者不会修改 Rust 宿主编译时使用的配置标识。所有验收副本均需独立便携项目标记，避免沿父目录找到正式项目。原生自检继续禁止打开用户 Workspace。

### 0.2.2 TFD 来源记录与迁入

项目保留可选 import_info：TFCalc 文件名、编码、解码后 UTF-8 文本 SHA-256、材料角色与精确目录映射、原始膜厚/组号/系数及未导入设置说明。原膜层和材料结构不变，物理厚度存实际值（源物理厚度乘组系数）。schema_version=1，数据库版本不变。

批量审计工具必须指定源目录及全新输出目录，拒绝覆盖或在源目录内写入。成功膜系写独立 Workspace；未支持项写逐文件清单。全部原件归档至 imports/TFCalc-originals.zip，附原始字节 SHA-256 清单；归档不代表被计算，应用不会自动执行或解析其中的内容。用户工作区和归档只保留本地。
