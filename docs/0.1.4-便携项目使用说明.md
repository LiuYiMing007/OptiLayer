# 0.1.4 便携项目使用说明

## 放到固态 U 盘

下载 Mac、Windows 0.1.4 包，解压后都以 TFC 文件夹为外层。两种系统共用时，将 macOS 和 Windows 两个程序子目录放到同一个 TFC 中，保留根部的 tfc-project.json。

```text
固态 U 盘/TFC/
  tfc-project.json
  macOS/TFC.app
  Windows/TFC.exe
  Windows/engine/...
  Workspace/
  .tfc/
```

Mac 打开 macOS/TFC.app；Windows 打开 Windows/TFC.exe。首次默认工作区是同一个 TFC/Workspace，后续选择以项目内的相对路径保存。

**搬迁时带走整个外层 TFC 文件夹，不要只复制 .app 或 EXE。** `.tfc` 是隐藏目录，会随整个文件夹一起复制。关闭应用后安全弹出磁盘。不要在两台电脑同时写入同一数据。

## 把 0.1.3 的数据放进来

1. 保留旧数据，先打开 0.1.4。
2. 点击顶部“项目内 · 工作区名”。
3. 选择“迁入旧工作区（复制）”，选择含有 workspace.json 的旧文件夹。
4. 程序会复制到当前项目的 Workspaces/import-…，不会覆盖原件。
5. 确认“我的项目”列表和计算结果，之后使用迁入后的项目内副本。

若旧目录本身已经在当前项目内，也可以直接用“打开项目内工作区”。后续不再读取本机系统目录中保存的旧绝对位置。

## 升级程序

退出 TFC；只替换 macOS 或 Windows 程序子目录。保留 Workspace、Workspaces、.tfc 和根部项目标识。不要删除整个旧项目后用一个空下载包替代。

两个下载包都不包含你的业务数据。GitHub 保存源码和程序版本，Workspace 仍需自行备份或随固态 U 盘携带。

## 出现位置错误时

- 检查是否只带了程序、遗漏了外层项目和 Workspace。
- 检查项目目录是否可写，磁盘是否已挂载。
- 新版本不会在失败时偷偷改存本机其它盘；提示缺失时，请恢复原数据或选择项目内正确工作区。
- 不要把空目录创建在旧位置来“消除错误”，这样不会找回原数据。

项目标识损坏、未来版本或错误的相对路径会明确报错；先保留文件和备份，再处理。
