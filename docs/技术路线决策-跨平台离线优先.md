# 技术路线决策：跨平台、离线优先、AI 原生

状态：2026-10-30 已采纳，基础架构版本 0.1.2。

## 决策

采用分阶段路线：**当前保留 Python / NumPy / SciPy 作为唯一生产计算实现；长期 Optical Core 优先迁移到独立 Rust 库，并以 WASM 复用到浏览器。** 这次不重写已经验证的光学公式，不同时维护两套生产业务算法。

当前客户端仍为 Tauri 2 + Rust 桌面宿主，React / TypeScript、Tailwind CSS 和 Plotly.js 共享界面。SQLite / UTF-8 JSON 保存到可迁移 Workspace；宿主负责 OS 路径、工作区选择和打包环境，计算内核不接触设备路径。AI 是未来的应用工具调用者，核心工作不依赖 AI 或联网。

Rust 是长期方向，**并非当前已经切换**。其科学计算需求尚须真实业务验证，尤其是带约束膜厚优化、终止/取消、容差和数值稳定性。迁移不能只以能画曲线或性能预期作为依据。

## 现状审计

保留：optics.py 的 S/P TMM、models.py 的具名材料和单位、analysis.py 的指标、原始 Golden CSV、裸界面和单层算例、独立 tmm 验证、React 编辑和图表。

原有冲突与本次修正：

| 原有问题 | 本次处理 |
|---|---|
| 数据默认写入应用数据目录中的单个数据库 | 引入有 manifest / 稳定 ID / 相对引用的 Workspace，宿主可切换目录 |
| main.py 同时承担解析、计算编排和持久化 | 拆出 application、repository、workspace、importers/tfd；main 只做进程适配 |
| .venv/bin/python、桌面计算程序名只适配 Mac | 启动与工具脚本加入 Windows Scripts/python.exe 和 tfc-engine.exe 分支 |
| 打包 / 产物整理仅支持 .app 和 ditto | 共享打包脚本、macOS .app 与 Windows 可携目录分别整理 |
| 无工作区搬迁或旧数据迁移测试 | 添加整目录搬迁、中文路径、旧库复制、版本拒绝、过期光谱和写入失败测试 |
| 浏览器预览绑定开发机隐式路径 | localhost 服务明确提供 TFC_WORKSPACE_ROOT；默认使用隔离的开发工作区 |

## Python 与 Rust/WASM 比较

| 维度 | Python Core | Rust / WASM Core | 结论 |
|---|---|---|---|
| TMM 与 2×2 复数矩阵 | 已实现并验证，NumPy 支持批量计算 | Complex64 与小矩阵可直接实现，无须大型线性代数库 | 语言不是主要科学风险，保持同一组验证标准 |
| 复数与临界角 | 当前已处理临界角解析极限 | num-complex 提供所需复数运算；仍须验证分支和稳定性 | 不因库存在就认为实现自动正确 |
| 色散模型 | 实现、拟合及实验方便 | Cauchy / Sellmeier 等纯函数适合移植 | 0.2.0 已支持用户 TFCalc 表格与公式；来源、适用范围和数值对照仍优先 |
| 后续优化 | SciPy 提供有界 least_squares、全局算法等成熟工具 | argmin 已有多种算法和 WASM 支持，但专业约束、鲁棒性需业务验证 | 当前保留 Python 避免提前丢失科学工具能力 |
| 自动测试 | 已有解析、Golden、独立实现验证 | 可做 Rust 单测及 native/WASM 同样本验证 | 测试样本与物理规范必须独立于语言 |
| macOS / Windows 桌面 | 每个 OS 分别打包 Python 环境；运行不需用户安装 Python | 原生库与 Tauri 集成自然，减少运行时分发负担 | 长期 Rust 更贴近部署目标 |
| 移动 SSD | 独立运行环境跟随各自 OS 客户端；数据用共同 Workspace | 同样需分别构建各 OS 程序；数据格式与语言无关 | 优先解决数据目录，不能把便携等同于单二进制 |
| 浏览器 | localhost 可以复用当前应用服务；本次只有开发预览 | Rust 核心可编译 WASM，计算不需要 Python 服务 | 长期 Rust/WASM 更贴近纯浏览器目标 |
| 维护成本 | 现在改动最少，验证资产现成；存在部署复杂度 | 未来统一 native/WASM 核心；迁移和优化生态需要投入 | 先隔离接口，达标后一次性替换生产核心 |

## Rust 迁移门槛

1. 保持当前统一数据模型、nm 单位、百分数输出、层序、偏振和误差定义。
2. 通过原始 301 点 Golden（≤1e-5 个百分点），解析算例、临界角、全反射、当前使用反馈及独立实现对照。
3. 在真实 macOS / Windows native 和浏览器 WASM 分别运行同一套样本，不以编译通过替代数值验证。
4. 对后续实际需要的优化任务验证算法、上下界、取消、重复性、敏感度和运行时间；本次不开发优化器。
5. 性能和打包成本实测达标后，再切换唯一生产 Optical Core；Python 仅保留离线验证/原型用途，避免两套业务逻辑长期分叉。

## 当前架构

```text
React / TypeScript UI
  └── src/api.ts：宿主传输适配
      ├── Tauri / Rust：窗口、目录选择、本机偏好、计算进程
      └── Vite localhost：开发适配（非独立浏览器发行版）
          └── engine/main.py：JSON 进程适配
              └── application.py：应用工具与编排
                  ├── optics.py + models.py：Optical Core
                  ├── analysis.py：光谱指标
                  ├── importers/tfd.py：TFCalc 子集导入
                  └── repository.py + workspace.py：数据与文件
                      └── Workspace：SQLite + UTF-8 JSON
```

未来 AI 通过同一 Application 工具接口读取上下文、调用专业计算、提出修改方案；当前没有 Agent、API Key、网络调用或优化器实现。

## 浏览器路线

近期先保持 localhost 与桌面使用同一 Python 应用服务。Vite 桥接目前只供开发测试，不把它称为可发行的离线浏览器版；发布浏览器版还需要单独的本地服务启动、静态资源分发与生命周期管理。

未来纯浏览器版使用 Rust/WASM Optical Core，并提供浏览器专用的数据适配器。WASM 只解决计算，不自动赋予本地磁盘权限，也不自动使网页离线可用。届时再设计用户授权的文件导入/导出、浏览器存储及静态资源离线缓存。本次不实现 WASM、PWA、浏览器 SQLite 或任意本地文件夹访问。

## 可验证范围

本机为 Apple Silicon Mac；已能实测 macOS 和目录搬迁。Windows 启动、构建和产物分支及 macOS/Windows CI 配置已加入，但没有在本机执行 Windows 二进制，不能宣称 Windows 发行版验收完成。移动 SSD 的真实文件系统、热拔插及另一台 Windows 电脑仍需实机验收。

## 主要依据

- [SciPy 优化工具](https://docs.scipy.org/doc/scipy/reference/optimize.html)：现有科学计算与后续优化评估。
- [num-complex](https://docs.rs/num-complex/latest/num_complex/struct.Complex.html)：Rust 复数运算能力。
- [argmin](https://argmin-rs.org/book/) 与 [WASM 支持变更](https://github.com/argmin-rs/argmin/blob/main/CHANGELOG.md)：候选优化生态，未据此声称专业任务已经验证。
- [wasm-bindgen](https://wasm-bindgen.github.io/wasm-bindgen/)：Rust 与 JavaScript 互操作方向。
- [PyInstaller 官方说明](https://pyinstaller.org/en/stable/)：按 OS 分别构建，不是一个程序跨 OS 执行。
- [SQLite 跨平台单文件格式](https://www.sqlite.org/onefile.html) 与 [锁定/文件系统说明](https://www.sqlite.org/howtocorrupt.html)：数据可迁移及使用边界。

## Windows 离线部署补充

Tauri Windows 客户端需要 WebView2。已提供 Windows 专用 offlineInstaller 配置，构建时准备离线安装程序；便携目录仍要求目标机器已具备 WebView2，不能宣称在任意全新 Windows 机器上零依赖运行。安装程序、签名、WebView2 离线安装与真实 Windows UI 尚待实机验收。[官方部署说明](https://v2.tauri.app/distribute/windows-installer/)。
