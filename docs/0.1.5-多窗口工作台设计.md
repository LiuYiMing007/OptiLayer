# 0.1.5 第二项：光谱主窗口与独立工具窗口

当前开发构建：0.1.5-dev.2。正式稳定版仍为 0.1.4，尚不创建正式 0.1.5 标签。

## 框架评估与实现

现有 Tauri 2 支持真正的多 WebviewWindow；保留 React、Plotly、Python Optical Core 与 Workspace 格式。无需更换桌面框架或复制计算实例。主窗口取消纵向 Dashboard，以可伸缩的 R/T 光谱和紧凑结果栏占据窗口主体；顶部保留高频入口、保存和手动计算。原有缩放、平移、悬停、参考波长、曲线开关、S/P 与目标曲线叠加继续复用。A 仍为 k=0 模型的数值残差，不是新增吸收模型。

桌面工具为原生、可移动/缩放/最小化的独立窗口：膜层结构、材料、基底、计算参数、项目、光谱分析、目标曲线。膜层表格独立滚动并固定表头，沿用最多 500 层的编辑约束。材料增加搜索及常数材料 JSON 导入；项目窗口集中项目名称、列表、保存、另存为及导入导出。复杂批量编辑、优化、公差等没有实现。

macOS 系统菜单控制所有窗口，工作区内不重复菜单；Windows 保留 dev.1 的独立菜单小窗口，并新增同一套工具窗口。窗口菜单控制显示/隐藏，顶部工具入口打开或聚焦对应窗口。浏览器开发模式使用同一数据逻辑的可拖动/缩放非模态浮动工具，避免依赖桌面 API；没有新增独立离线浏览器产品或弹出式浏览器窗口。

## 唯一状态与命令

```text
系统菜单 / Windows 菜单窗口 / 工具窗口
               ↓ 定向命令
主光谱窗口协调器（唯一 Project / Workspace State、历史、保存、计算队列）
               ↓                       ↑
       现有应用服务 / Optical Core     只读状态投影 + 命令确认
               ↓                       ↑
      Workspace / SQLite / JSON      各工具窗口
```

工具窗口不挂载 App，不直接调用存储、材料库或计算接口。它们接收只读投影，提交编辑意图，由主协调器调用原有逻辑。投影是显示数据，不能作为整份项目回写。膜层修改以稳定 ID 定位，字段携带旧值；不同字段并行修改可合并，同一字段被另一来源更新则整批拒绝，避免静默覆盖。连续输入的同来源命令允许顺序落地。项目/工作区切换及撤销重做更换 scope，拒绝迟到的旧命令。

Rust 层从真实窗口标签取得来源，命令只发往主窗口，重复 requestId 拦截。工具仅能请求投影和提交意图，不能发布权威状态或访问主窗口专用业务接口。主窗口回传确认及最新投影；不需要主窗口处于前台或动画帧运行。

计算不阻塞工具编辑。物理输入变化后约 180 ms 自动计算，计算队列最多一个执行中和一个可替换待执行任务；旧结果与旧错误不会覆盖最新输入。手动计算保留。未改动 Optical Core、TMM、TFD 解析器或 Workspace 数据模式。

## 窗口与便携布局

关闭工具只隐藏，重新打开仍展示同一项目；不删除膜层。主窗口退出沿用未保存确认，确认退出后销毁所有工具及 Windows 菜单窗口。首次启动只显示主光谱（Windows 另有菜单小窗口）。

窗口位置与尺寸保存在便携项目内 `.tfc/window-layout.json`，按 macOS/Windows 分区，记录显示器名称、相对位置及逻辑尺寸，不写电脑绝对文件路径。断开外接显示器或更换设备后回落主显示器并限制在可见范围。位置自动记忆；“窗口 → 下次恢复工具窗口布局”默认关闭，开启后恢复上次可见工具。它只恢复布局，不自动打开未保存项目；项目仍需显式保存。跨系统共用 Workspace，分别保留布局，不强迫两种系统使用同一像素坐标。

## 扩展入口与边界

`src/tools/windows.json` 定义工具标题、尺寸、最小尺寸，Rust 与 React 共用；`ToolView` 连接业务组件，`menus.json` 连接命令。增加专业工具时扩展注册表、受控视图及菜单；目前没有实现优化、目标自动求解、AI Agent、容差、工艺或多项目并行编辑。

浏览器浮动布局只在当前会话内有效。桌面多显示器实际排列、Windows 真实显示缩放与快捷键手工体验仍需真实设备验收；自动原生窗口测试覆盖创建、关闭隐藏/恢复、来源权限、投影序号及单次命令路由。
