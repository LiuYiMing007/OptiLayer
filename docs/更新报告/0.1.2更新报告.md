# TFC 0.1.2 更新报告

发布日期：2026-10-30。版本主题：跨平台基础架构与可迁移 Workspace。

## 本版完成了什么

0.1.2 将原来的 Mac 本机项目存储，调整为可以整体复制和重新打开的 Workspace，保留原有正确的光学计算、材料校验、光谱分析与编辑界面。目标是让“新建项目 → 材料与基底 → 膜系编辑 → 计算 → R/T 光谱 → 保存项目”具备可靠的数据基础。

### 1. 建立统一工作区

- 支持在桌面界面新建、打开、切换及重新连接工作区。
- 项目、材料、光谱、数据库集中在一个目录中，使用 Workspace v1 标识与版本。
- 内部文件引用采用相对路径；电脑上的工作区位置只保存在本机偏好中。
- 移动硬盘未挂载或目录不存在时提示重新选择，不创建替代空工作区。
- 首次升级将旧数据库复制到默认工作区，原数据库保留；原有 3 个项目迁移通过。

### 2. 保存项目与可追溯光谱

- SQLite schema v3 作为项目和共享材料的主存储。
- 项目、材料同时保留 JSON 恢复副本；JSON 副本不是自动覆盖数据库的另一份主数据。
- 保存项目时，归档与当前物理输入一致的有效光谱，包含输入快照与单位。
- 拒绝把过期光谱附到已修改的项目；JSON 副本写入失败时保留已提交的数据库并提示。
- 修复原生 JSON 字段顺序变化导致错误判定“结果过期”、跳过光谱归档的问题。

### 3. 分离计算与文件、存储职责

```text
React 界面 → 桌面宿主 → 应用服务
                         ├─ Optical Core / 光谱分析
                         ├─ TFCalc 参考子集解析
                         └─ Workspace / SQLite / JSON
```

保留 `optics.py`、`models.py`、`analysis.py` 的计算、校验与分析实现；新增工作区、存储和应用服务模块，将 TFCalc 子集解析从入口分离。计算不依赖 UI、数据库、AI 或具体导入文件格式。

### 4. 明确长期技术路线

继续采用 Tauri 2、React / TypeScript、Tailwind CSS 和 Plotly。Python / NumPy / SciPy 是当前唯一生产计算实现；长期优先考虑 Rust 原生 / WASM，但必须先通过数值、模型、性能与后续优化需求验收。本版没有维护第二套生产算法。

补充 Windows 启动路径、打包脚本、图标和 CI 检查流程，为后续实机构建准备基础。

## 本版边界

0.1.2 发布时仅完成 Apple Silicon Mac 验收；Windows 实机、真实 SSD 往返及独立浏览器产品尚未验收。Windows 构建和数据兼容验证随后在 0.1.3 继续完成。

当前物理模型仍为常数实数折射率、k=0、单面相干膜层、半无限边界，不含基底背面反射。未实现真实色散/吸收、Rust/WASM Core、AI Agent、膜系优化、云同步或冲突合并。原有厚度联动、入射角、材料/基底选择及光谱交互继续保留。
