# 0.2.4 更新报告

本版修复紧凑材料、基底窗口无法新增和删除的问题。保留现有光学计算、材料常数与项目文件格式。

## 材料与基底管理

- 材料、基底窄列表均提供“新增…”与“删除…”，空列表也能新增。新增会打开独立材料数据窗口，填写名称、用途和常数 n/k，亦可选择逐波长数据表或色散公式；保存后同时写入共享库、当前项目和独立文件。
- 新增基底不会自动替换当前项目基底，选择后点击“设为基底”才应用。已在使用的材料编辑继续使用项目快照更新和原有撤销、自动计算逻辑。
- 共享目录删除有紧凑确认及“撤销删除”，删除状态随 Workspace 保存，重启、搬迁后不会自动重新出现。已有项目中的材料快照不受影响，因此历史膜系仍能复算。
- “当前项目”删除检查前后表面膜层、入射介质、基底及出射介质引用，指出使用位置；先替换再删除。未使用的项目材料可移除并通过项目撤销恢复。
- 不再设置“自定义”分类；手工新增和导入材料在同一列表中搜索选择。原目录来源筛选仍保留用于识别同名数据。
- 清理早期四条未修改演示常数：TA2O5_REF、SIO2_REF、AIR、GLASS_REF。仅清理共享库的原样记录；用户修改过的同名记录、所有项目快照及原始 TFCalc 数据保持完整。新工作区不再预置这四项共享记录，参考项目仍包含自身的计算快照。

## 数据位置与恢复

- 膜层材料：`Workspace/materials/films/<名称>.material.json`。
- 基底与介质：`Workspace/materials/substrates/<名称>.material.json`。
- 原始 TFCalc 资料仍在 `materials/catalogue`、`materials/substrates/<原始来源>`；原件保留。删除目录中的原始条目属于移出当前共享目录，不销毁原始来源。
- 删除记录的完整备份保存在 `materials/deleted/`；当前窗口可撤销上次共享目录删除，重启后也可通过“导入 JSON → 保存到共享库”恢复对应备份。文件中含原名称和完整数据。
- 旧的共享材料恢复文件会迁入 films/substrates；手工改动过的旧文件保留，不擅自删除或覆盖。
- 数据库升级为版本4，以保存删除状态；项目文件格式不变。请同时更新两端到0.2.4，升级前备份整个便携项目。旧客户端不应继续写入升级后的工作区。

## 验证

本机通过69项 Python 引擎/存储测试、55项 TypeScript 测试、8项打包/迁移测试、12项 macOS Rust 测试及25项数值检查。新增覆盖材料与基底新增、修改、删除、恢复、逐项文件、搬迁复算、原始目录删除状态、旧演示记录清理、并发数据冲突、手工修改文件保护、项目引用拦截。

隔离浏览器工作区实际操作验证新增膜层材料、新增基底、搜索、删除及恢复。原生多窗口检查增加材料及基底“新增、删除、撤销删除”的真实按钮与 IPC 检查，冻结运行时目录验收增加两类数据的创建、删除和恢复，以同一套流程在 macOS/Windows 构建中执行。

[实际运行界面](../v0.2.4-material-management.png)。本机签名校验、15个原生工具窗口及菜单打开、材料管理按钮 IPC、冻结材料/基底增删恢复、目录显示和便携搬迁均通过。

Golden 最大误差仍为 `7.838345368327282e-7` 个百分点。本次没有改动 Optical Core 公式、材料常数、AI Agent 或自动优化。
