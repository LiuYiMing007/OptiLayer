# TFC 0.2.2 更新报告（开发验证，尚未正式发布）

本版修复数据位置难找、不同安装误共享定位、TFD 导入范围过小及导入失败容易误认旧曲线的问题。已使用用户提供的全部 771 个 TFD 做实际检查和独立工作区迁入。没有改写已验证 Optical Core、原始光学常数或 Golden。

## 数据位置与交互

取消 0.2.1 的机器全局 project-location.json 自动恢复与写入。正常便携启动继续按本项目相对路径定位；显式选择只作用当前会话。隔离启动无法辨认原位置时需明确选择，不自动连接其它安装或验收目录。

主窗口常驻“数据位置”入口，紧凑面板显示工作区、膜系、材料与基底、保存光谱、导出目录的完整路径，均可直接打开。说明保存后才会生成项目文件，以及材料与基底共用材料库。压缩包说明改为 ASCII 文件名 README.txt，避免解压乱码。

导入失败明确显示文件、原因及原曲线所属项目；原项目不被替换。支持重新选择文件。导入/切换项目时图表视口重置，同一项目内连续编辑保留缩放。

验收使用真正的 Tauri 编译配置 identifier 隔离，不再仅修改 Info.plist；测试副本自带便携标记，不触碰正式 Workspace。

## TFD 实际兼容扩展

新增 UTF-8/GB18030 严格解码；膜层只按 MATERIAL 名称解析，基底/入射介质只按 SUBSTRAT 名称解析，保留完整 n/k，不跨目录模糊替代。原始物理厚度乘分组系数后进入项目；保留层序、参考波长、角度及 A/S/P 偏振。

原始文件名、编码、解码文本校验、材料映射、原始膜厚/组号/系数和未导入内容随项目保存，可在项目窗口展开查看。导入前项目的目标曲线、分析波段不带入新项目。旧合成 REF 验证样例继续沿用原常数路径。

项目列表增加多关键词搜索及每页 50 项，支持此批数百个膜系的查找。

## 全量检查结果

- 全部 771 个 TFD 逐一检查，其中 16 个按 GB18030 解码。
- 621 个完成解析、计算、保存、载入及精确复算，写入独立 Workspace。
- 150 个明确拦截，没有丢弃背面膜层、忽略基底背面或填入默认材料。原因存在交叉：141 个需要有限厚基底/出射界面模型，24 个含背面膜层，4 个有缺失或乱码材料引用。
- 包括其它资料在内的 812 个原文件前后 SHA-256 均未改变，另在本地迁入工作区的 imports/TFCalc-originals.zip 完整归档并逐个核对。

[详细兼容验收](../0.2.2-TFD实际兼容验收.md) 与聚合 JSON 随代码保存；用户原件、逐文件清单、材料参数及迁入 Workspace 均不上传 GitHub，也不混入程序发布包。

## 当前边界

仍未实现有限厚基底、双面膜系、反向入射、变量/混合材料、全部 TFCalc 分析/优化设置。材料问题包括 100、SY1 与乱码名称，没有自行猜测。此批验收证明内部保存/复算链路，不等于 771 份原 TFCalc 光谱对照验证。

没有开发 AI Agent、膜系优化或重写计算引擎。项目 schema_version 和数据库版本不变，仅附加可选 import_info 来源记录。

## 验证与交付

52 项引擎 Python、30 项 TypeScript、7 项打包/迁移 Python、11 项 Mac Rust、25 项数值检查通过。Mac 打包程序的中文解码、真实材料、组系数、错误拦截、搬迁复算、菜单和真实多窗口检查通过；冻结引擎新增验收脚本也接入 Windows CI。Windows 本轮状态以 Actions 实际结果为准。

本地提供新版 Mac 开发验证包，以及包含 621 个迁入膜系与原件归档的私人便携项目；二者分开，私人数据不得作为公共安装包上传。当前不创建正式版本标签，0.2.1 的发布包与标签不变。

## Windows 发布前复核

修复迁入报告在 Windows 旧区域编码下遇到中文写入失败的问题，输出统一 UTF-8，归档内部名称统一 POSIX 相对路径。补充中文文件名、中文子目录及 cp1252 默认编码模拟检查。

工作区面板补齐 database / imports / config，与项目、材料、光谱、导出共七类目录均可直接打开。新增冻结引擎 + 原生宿主目录验证：在中文路径创建副本，保存项目、光谱、数据库和材料目录，搬迁后逐一调用生产文件管理器打开逻辑并复算。

当前本机 52 项引擎 Python、34 项 TypeScript、8 项打包/迁入 Python、12 项 Rust、25 项数值检查通过。Windows 最新发布前构建正在重新验证；通过后再创建不可变正式标签。手机框架属于独立预览，不视作 iOS 正式发行或真机验收通过。

Windows 文件夹打开时将文件系统规范路径转换为资源管理器可识别的路径，保留中文、空格和网络共享；子进程不继承验收输出管道。Windows 目录检查将通过 Shell COM 核对八个目标窗口的位置，并仅关闭本轮测试窗口。

发布前复核中已定位并修复资源管理器验收脚本的 PowerShell 数组嵌套问题；此项将重新执行，不将失败运行作为通过证据。构建缓存只保存已编译程序，后续仍执行全部打包验证。

资源管理器实际已打开全部八个目标窗口；验收进一步改用目录身份核对，处理 Windows 8.3 短路径与完整路径名称不同造成的误报。
