# 0.1.5 跨平台菜单与窗口

本文记录第一项菜单设计；当前构建已进入 **0.1.5-dev.2**，第二项以 [多窗口工作台设计](0.1.5-多窗口工作台设计.md) 为准。尚未发布正式 0.1.5 标签，数值模型保持不变。

## 呈现

- macOS：系统顶部原生应用菜单，主工作台内不重复显示。保留系统文本撤销、剪切、复制、粘贴和全选。
- Windows：同一个 Tauri 应用创建独立 `menu` WebviewWindow，原生标题显示软件名，其下是紧凑横向原生菜单栏，内容显示当前项目、工作区和未保存/处理状态。主工作台不增加相同菜单栏。菜单窗可独立移动、最小化和收起，不设总在最前。
- 浏览器/开发预览：应用内下拉菜单，使用同一菜单配置与命令处理；不调用桌面菜单 API。浏览器生产版的计算服务范围保持原状，未新增完整浏览器产品。

## 状态与调用

`src/menus/menus.json` 是唯一功能菜单目录，Rust 与 TypeScript 同时读取。当前九类为文件、编辑、膜系、参数、计算、分析、窗口、工具、帮助。dev.2 已连接项目另存为；批量编辑、优化及公差分析仍灰显。

原生命令 → Rust 定向发送 `menu-command` 给 `main` → App 当前命令处理 → 原有更新、撤销、计算、导入/导出或保存函数 → 状态回传原生菜单及 Windows 菜单窗口。

- `main` 是唯一的项目、编辑历史、光谱与工作区状态持有者。菜单窗口不挂载 App，不请求计算、不加载另一份项目、不启动额外引擎。
- `menu_sync` 只有主窗口可调用；工作区及引擎 IPC 同样限定主窗口。辅助窗口仅监听/读取菜单状态。
- 前端监听就绪后才启用原生菜单；状态发布串行合并最新快照。忙碌、有对话框或确认待处理时禁用命令，主端处理时再次检查。
- 无工作区时禁用打开/保存，但保留工作区恢复和纯光谱计算；没有选中层时禁用复制/删除/材料替换，达到 500 层上限禁止继续添加；过期光谱禁止导出。
- 膜层工具栏与菜单调用同一 `changeLayer`；光谱 CSV 菜单与图表按钮使用同一导出序列化函数。dev.2 主窗口改为光谱与高频工具入口，原纵向导航及编辑区域拆成工具窗口。
- 窗口菜单管理真正的工具窗口；关闭只隐藏，不清空项目。支持收起所有工具与按系统记忆布局；恢复可见工具为用户主动开启。参数菜单打开并聚焦对应工具输入。
- 原生菜单导入使用原生文件选择器，共用原有 TFD/JSON 解析验证链路，避免依赖浏览器用户手势才能弹出文件选择器。

## 快捷键与生命周期

- 新建 Cmd/Ctrl+N，打开 Cmd/Ctrl+O，保存 Cmd/Ctrl+S，导入 Cmd/Ctrl+Shift+I，导出项目 Cmd/Ctrl+Shift+E，添加膜层 Cmd/Ctrl+L，复制选中膜层 Cmd/Ctrl+D，计算 Cmd/Ctrl+Enter。
- Windows 膜系撤销 Ctrl+Z，重做 Ctrl+Shift+Z；在文本输入中保留标准文本撤销。
- macOS 文本撤销仍是 Cmd+Z；明确的“撤销膜系修改”使用 Option+Cmd+Z，重做 Option+Shift+Cmd+Z，以避免抢占系统文本响应链。
- 快捷键说明来自同一目录。原生 Mac 由系统菜单处理快捷键，避免网页重复触发；Windows 主窗口、工具窗口与浏览器使用同一目录匹配快捷键。原生命令保留当前工具焦点，需要确认或对话框时由主协调器聚焦主窗。
- 关闭 Windows 菜单窗口只隐藏，不退出或销毁主工作台；主窗口“显示菜单窗口”按钮可恢复，显示的状态仍来自主窗口。
- 菜单退出、系统退出请求和主工作台关闭经过原有未保存确认；确认期间阻止重复提示；存储处理未完成时先阻止关闭；自动计算允许继续编辑，旧结果不会覆盖新输入。放弃修改关闭主窗口后，辅助窗口也销毁，应用结束。
- Workspace 定位、相对设置、跨平台数据格式完全沿用 0.1.4。升级正式程序仍保留 Workspace、Workspaces 和 .tfc。

## 验证入口与边界

dev.2：32 项 Python、17 项 TypeScript、Mac 10 项 Rust（Windows 9 项）及既有 25 项数值检查。新增测试关注菜单门控、快捷键不抢文本编辑、唯一命令/快捷键和共用膜层操作的物理参数/层序。

`--menu-self-test` 是隔离的原生验收入口：主 webview 加载空白页，不运行 App 或计算引擎，不打开工作区；在实际原生事件循环内检查菜单类别、启用/勾选同步、命令到主窗且仅一次、禁用命令拦截，以及 Windows 菜单收起/恢复、工具创建/关闭隐藏/再开、投影序号、命令去重和辅助窗口权限。`validate_menu_release.py` 检查其返回值、超时及 Workspace/.tfc 哈希不变。CI 在各自系统执行；Windows 视觉位置、手工点击体验仍须真机人工检查。

最终 dev.2 测试包放在 `release/0.1.5-dev.2-verified/TFC/`，不附个人数据；界面验收数据单独保存在 acceptance。原有 `便携项目/TFC` 和 0.1.4 下载版保持可用。

dev.1 历史结果：[双平台 CI 成功](https://github.com/LiuYiMing007/tfc-workbench/actions/runs/41262492504)。Windows 已完成原生窗口自动验收，实际设备视觉和手工交互仍待检查；Mac 原生点击及浏览器兼容点击已完成。本机开发目录已合并双平台程序，原生点击测试数据移至 acceptance 保留，开发目录首次启动创建独立 Workspace。
