# 0.2.0 材料目录与计算设计

## 数据链路

`MAT 只读提取 → 内置标准化目录 → 索引摘要检索 → 按名称载入完整记录 → Project 材料快照 → Optical Core → R/T/A → Workspace 保存`

- `engine/importers/mat.py`：独立读取原 MAT，不执行外部程序。`scripts/import_tfcalc_catalogue.py` 确定性生成 `engine/data/tfcalc-catalogue.json`。
- `engine/catalogue.py`：只读内置目录。`library_list` 将目录摘要与工作区用户共享库合并；不会向现有数据库灌入上千行或覆盖同名用户材料。
- 多窗口只接收摘要，最多 50 行 DOM；预览曲线缩减采样。`catalogue_get` 由主窗口调用，返回未降采样的完整快照；目录摘要和待核查项不能充当计算材料。
- 新导入名称为 `TFC/<集合>/<原名称>`，原名称、来源目录和原文件 SHA-256 独立保存。不同来源的同名材料不会被覆盖。物理内容一致的记录标注 `duplicate_of`，仍保留原身份。
- 材料／基底共用紧凑目录组件。支持多关键词、中文名、来源／用途／状态筛选、分页、↑↓ 选择和 Enter／双击应用。基底窗口直接“设为当前基底”，无需先手动添加再去别处切换。
- 所有写入仍经过唯一主窗口 Project State、历史记录、自动计算队列；关闭工具窗口不删除材料，也不启动第二个计算实例。

## 光学模型

原 `constant` 模型和旧项目格式继续可读。新增可选字段：

- `tabulated`：`samples = [[wavelength_nm,n,k],…]`，`range_nm`、原点数及 `range_policy=endpoint`。
- `tfcalc-formula`：模型编号、n 的六个系数和 k 的三个系数、`range_nm`、`wavelength_unit=um`。保留公式而非固化为 550 nm 的 n。
- `n/k` 仍用于目录预览兼容；生产计算以 `materials.optical_constants()` 在每个计算波长求值。前端 `materialAt()` 只用于参考波长下的显示和 d / n·d / QWOT 换算；输入计算的始终是物理厚度。

既有无吸收常数项目继续使用原特征矩阵函数，保持 Golden 验证结果。色散／吸收材料使用后向散射递推，避免厚吸收膜指数增长溢出；正 k 为吸收，使用 n+ik 的传播约定、衰减的前向复数根。S/P、金属膜、多层反序、吸收基底与独立 `tmm==0.2.0` 对照；它仅是测试依赖，不作为生产引擎。

A=1−R−T 表示进入半无限基底之前膜系吸收；不包含基底内部后续全部吸收或背面反射。无吸收时仍是数值残差。不归一化、不裁剪光谱来隐藏误差。吸收模型的 `energy_error` 记录被动性违反 max(R+T−1,0)，`energy_check=passivity_violation`；无吸收记录 |R+T−1|，`energy_check=lossless_residual`。R+T+A=1 在吸收模式中是定义，不当作独立能量验证。

当前仍不支持吸收入射介质、负 k 增益、各向异性、背面反射或非相干厚基底；这些情况不伪装为支持。原始库中的数值不等同于实际镀膜工艺的测量值。

## 便携和升级

完整目录作为资源一起打入 Mac 和 Windows 的 Python Runtime，不需要原 TFCalc 文件夹、网络或系统 Python。项目保存完整选用快照，独立于全局库；更换程序、材料目录或移动 Workspace 不自动改变历史项目。现有 SQLite、工作区 manifest 与项目 `schema_version=1` 不变，新材料模型是附加字段；包含色散／吸收的新项目应使用 0.2.0 或更高版本打开，0.1.x 无法计算新模型。旧项目升级无需重算或转换原材料为真实库条目。

光学常数模块是纯函数，不读取目录／文件／数据库；未来 Rust/WASM 可以复用同样的数据契约和验证，但本版未做语言迁移、AI Agent 或优化器。
